# CLI Contract: `oboete` (M1)

Binary: `oboete` (npm `bin`), entry point `dist/oboete.mjs`, which since issue #210 is the launcher that enables the V8 compile cache and imports the engine, `dist/engine.mjs`, beside it. All commands accept `--json` where output
is listed as structured. Exit codes: `0` success or explicit empty/degraded result, `1` target not
found or partially degraded, `2` invalid input or confirmation missing, `3` storage or I/O failure.
Commands invoked by agents (`hook`, `capture`, `inject`) always exit `0`.

| Command | Purpose | Input | Output |
|---|---|---|---|
| `oboete setup [--agents claude,codex,grok,pi] [--provider <preset>] [--accept-egress] [--yes] [--remove]` | Detect installed agents; for a remote preset show destination host, credential source, cost class, and egress, then require confirmation (`--accept-egress` on the command line, or `--yes` only when the stored consent hash equals the hash of the tuple setup would display now: preset, host, credential source, cost class, egress classes); write hook and extension configuration through oboete-managed blocks (backup preserving mode and owner, 0600 for credential-bearing files; write to a temporary file, re-parse, rename); handlers carry fixed `--agent` selectors; write trust entries; run headless probes for all selected agents in parallel under a 90 s deadline; report trust state and native-memory warnings ; when the default preset's credentials are missing, print the Cloudflare free-account and Workers AI token steps with URLs and offer `--provider ollama`, `--provider agent-cli`, or continuing without a provider (rule-based) instead of failing; always print the `oboete view --open` launch line | flags | table or JSON: per agent `wired`, `probe`, `trust`, `native_memory`; exit `1` if any probe failed, `2` if consent is missing |
| `oboete doctor [--probe-provider] [--no-probe-agents]` | Hook wiring by a fresh headless wiring probe per agent (default on, parallel, 90 s; `--no-probe-agents` shows the last result marked `unverified`, never `healthy`) and trust state; provider reachability by a live call only with `--probe-provider` (counts against the daily cap), otherwise the last outcome marked `unverified`; storage integrity and FTS5, migration level, worker liveness, spool backlog and writability, provider reachability, estimated allowance and exhaustion flag, catalog paid-plan flag, unrecognized agents, native memory coexistence, config file mode, Pi diagnostics. The report also states that search is lexical in M1 and prints the `oboete view --open` line. Every item has the shape `{ item, status, reason, consequence, recovery }`: `consequence` states what the developer loses while it is degraded (for example "Codex sessions capture nothing"), `recovery` states the command or step that repairs it (for corrupt storage: back up the file, run `oboete export` if readable, move the database aside, run `oboete setup`, import the export) | | table or JSON; exit `1` when any item is degraded, `3` on storage integrity failure (`warning` and `unverified` do not change the exit code; integrity failure is a file that is not a database, a corrupt header, or `PRAGMA quick_check` other than `ok`) |
| `oboete hook --agent codex\|claude-or-grok --event <name>` | Agent-invoked entry: resolves `claude-or-grok` from `GROK_HOOK_EVENT`/`GROK_SESSION_ID`, checks the paused marker, reads at most 256 KiB of stdin, runs the detector before any write, captures or spools (the read part of a larger payload is kept as a redacted `partial` row marked truncated, A7), prints a plain-text pack on injection events | stdin JSON | pack or nothing; exit `0` |
| `oboete capture --agent pi --event <name> --invocation <id> [--prior-failures <codes>]` | Pi's detached capture child; writes `spool/pi-ack/<invocation>.started` before reading stdin and renames it to `.done` on completion; records the extension's in-memory failure counters as diagnostics | stdin normalized event | none; exit `0` |
| `oboete inject --agent pi --kind start\|prompt` | Pi's bounded injection child | stdin `{ cwd, session_id, prompt? }` | pack or empty; exit `0` |
| `oboete observe` | Detached worker: recover spool, claim the fenced lease, purge expired rows, batch by destination, classify, summarize with deadlines, apply, checkpoint, release atomically with the empty-queue check | | `~/.oboete/logs/observe.log`; exit `0` (done or another worker live), `1` fallback used, `3` unrecoverable storage error |
| `oboete search <query> [--limit N]` | Same-repository active memories by relevance (repository from cwd; shared query function, `destination = injection`)  | | list with scores and reasons; an empty result exits `0` with a reason and the note that M1 search is lexical (word match), semantic search arriving in M2 |
| `oboete timeline [--session <id>]` | Sessions, turns, memory metadata | | list |
| `oboete get <memory-id>` | One memory with provenance within the cwd repository boundary | | record; `1` if absent or out of boundary |
| `oboete why <session-id> [--turn N]` | Injection ledger with reasons, trims, staleness, deferred and degraded state | | report |
| `oboete pin <id> [--order N]`, `unpin <id>`, `delete <id>` | Pin state and tombstone | | confirmation |
| `oboete pause`, `oboete resume` | Create or remove `~/.oboete/paused` | | confirmation |
| `oboete export [file\|-]` | JSONL `oboete-export/1` with active memories and tombstones | | count |
| `oboete import [file\|-] [--dry-run] [--map-repo <old-id>=<current>]` | Per-line validated import (64 KB per line, 256 MB per file), `material_hash` verified against the body, `content_hash` recomputed from the local repository id, union on `content_hash`, lattice `secret > private > local_only > eligible`, tombstones win, active rows land as `local_only` / `review_state = imported` and stay out of search and injection until the worker classifies them; `--map-repo` maps a machine-local (`common_dir`) repository identity from another installation onto a repository here | | counts; `2` on invalid format |
| `oboete mcp` | Legacy-era stdio MCP server (`search`, `timeline`, `get`) under the cwd boundary | stdio JSON-RPC | see `mcp.md` |
| `oboete view [--port N] [--open]` | Local viewer on `127.0.0.1` with a per-launch token; `--open` launches the browser on the tokenized URL | | URL; foreground; `2` on non-loopback host |
| `oboete fixture replay <file> [--pass-credentials] [--settle-ms <ms>]` | Replay native payloads through the real hook and record evidence. The hooks and workers it starts get no oboete credential variable, unless `--pass-credentials` keeps them to evaluate a remote preset (only values of at least 8 characters, the ones it scans for). That flag is refused (exit 2) before anything starts, and a temporary home it made is removed, unless the home's consent record matches its configuration (the consent rule of R8: a preset that sends nothing off this machine needs no record), and any kept value found in a written surface, a pack or a child's output fails SC-005 by name; the one exception is `OBOETE_CF_ACCOUNT_ID` in the `runtime_state` row `workers_ai_catalog`, where the Workers AI catalog cache stores it by design (#328). `--settle-ms` sets the fixed bound of each wait for the worker to settle the ended sessions (default 300000, exit 2 unless a positive whole number); the worker it starts stops at its own 20-minute run cap and is not restarted within a wait, so a bound above 1200000 only delays `worker_settle_timeout` | | `docs/evidence/m1-resource-envelope.md` |

Environment: `OBOETE_HOME` relocates the data directory; `OBOETE_CF_API_TOKEN`,
`OBOETE_CF_ACCOUNT_ID`, and one `OBOETE_<PRESET>_API_KEY` per preset (`OBOETE_NIM_API_KEY`,
`OBOETE_OPENROUTER_API_KEY`, `OBOETE_GEMINI_API_KEY`) supply
credentials without writing them to the config file; `OBOETE_TEST_FAULT` and `OBOETE_TEST_FAULT_URL` are honoured only when `NODE_ENV=test`; the redirected request carries no credential header, and a target outside numeric loopback, a non-HTTP scheme, or a process whose fetch goes through Node's environment proxy (`NODE_USE_ENV_PROXY`, `--use-env-proxy`) leaves the request unredirected.

Output rules: packs are plain factual text framed by the label lines `oboete memory context` and
`end of oboete memory context`, never start with `{`, and quote bodies with a `> ` prefix.
Diagnostics and logs never contain credential values or redacted content. The remote observer never receives the normalized repository identity or path, only the repository id.
